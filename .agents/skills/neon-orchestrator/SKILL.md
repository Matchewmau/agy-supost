# Choose the execution path

Read the project rules and acceptance criteria. Resume from existing trackers on multi-session builds. For greenfield work, use project-bootstrap, agree shared contracts, and checkpoint a passing foundation before dispatch.

- **Bounded fix or dependent slices** — use the built-in Orchestrator in one conversation. Start at the supplied symbols and tests. Settle any shared contract before reconsidering parallelism.
- **Two to four independent slices** — assign disjoint files and stable interfaces to saved builders in separate `share` or `branch` workspaces. Send goal, ownership, contract, acceptance criteria and check command. Reuse the same worker for follow-ups.
- **Larger independent batches** — use `run_workflow` for repeatable tasks with checkable outputs. For invocation examples, escalation briefs and project trackers, consult the [coordination reference](references/subagent-templates.md) as needed. For persistent multi-day teams consider `/teamwork`; the user starts `/swarm`.

Scout once with explorer only when ownership is unclear or several builders need the same map. Use flash for mechanical work and inherit/pro for implementation. Check the parent model when using inherit. Escalate shared-contract blockers immediately and repeated failures after two attempts at the same check.

## Verification

Builders run focused checks. After integration, inspect the actual diff and run required final checks in the target workspace. Use independent review for cross-slice changes, auth, migrations and shared contracts; lead review suffices for a bounded fix. Record milestone evidence and checkpoint verified work according to project conventions. Batch durable updates through phase-handoff at a milestone or session boundary.
